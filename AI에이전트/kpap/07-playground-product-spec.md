# kpap Playground 상세 기획

검토용 v0.4. 사용자 목표는 설정을 검증하고 운영 품질을 개선하는 것이다. 이 문서가 화면·행동의 기준이다.

## 기능과 정보 구조

프로젝트 → 에이전트 → 환경을 유지한다. 주 메뉴는 개요, 작업공간, 온라인 평가다. 작업공간에서 노드별 설정·실행·오프라인 평가를 함께 수행한다. 이력은 사이드바로 연다. 배치는 [노드 작업공간 UX](09-node-workspace-ux.md)를 따른다.

| 영역 | 기능 |
|---|---|
| 설정 | 초안·프로필·버전·검증·차이·활성 참조·복구 |
| 실행 | 입력·응답·스트림·추가 입력·취소·이력·재실행 |
| 관측 | 내부 처리·모델·도구·RAG·오류·재시도·사용량·비용 |
| 오프라인 평가 | 데이터셋·평가기·실험·로컬/플랫폼 실행·비교 |
| 온라인 평가 | 정책·시험·표본·예산·품질·커버리지·문제 조사 |
| 환류 | 운영 사례 검토·정답 작성·데이터셋 반영·재평가 |

## 화면 원칙

작업공간은 노드 흐름·선택 노드 설정·결과를 함께 보여준다. 실행·평가는 같은 편집 구조를 사용한다. 항목·노드 관측은 본문에서 조사한다. 과거 실행·실험은 이력 사이드바에서 선택한다.

각 단계는 주 행동 하나를 강조한다. 기본 화면은 이름·버전·결과를 보여준다. JSON·내부 ID·고급 옵션은 필요할 때 펼친다. 저장과 운영 반영은 분리한다.

목록 필터·선택·스크롤·초안을 유지한다. 결과에서 설정·평가 근거·관측으로 바로 이동한다. 공유 링크는 접근권한을 넓히지 않는다.

## 설정과 평가 규칙

- 설정은 실행 시작에 확정한다. 적용 확인 전에는 적용됨으로 표시하지 않는다.
- 초안 시험도 불변 스냅샷을 만든다. 운영 적용은 저장된 버전만 사용한다.
- 활성 참조 변경은 새 요청에만 적용한다. 기존 실행은 유지한다.
- 데이터셋·코드·평가기·설정 버전을 실험에 고정한다.
- 정답은 평가기에만 전달한다.
- 점수 척도·입력·평가기 버전이 다른 결과는 직접 비교하지 않는다.
- 실패·제외·평가 오류는 낮은 점수와 구분한다.
- 온라인 정책 변경은 새 버전을 만든다. 시험 결과는 운영 집계와 분리한다.
- 표본·추가 오류 수집 집단을 혼합하여 전체 품질로 표시하지 않는다.
- 수동 검토·피드백·자동 평가는 출처를 분리한다.
- 자동 점수로 정답·운영 승격·원인을 확정하지 않는다.

## 상태와 복구

| 상태 | 표시와 행동 |
|---|---|
| 설정 적용 대기 | 적용 확인 중 |
| 관측 수집 중·부분 수집 | 응답 유지·도착 구간 표시·재조회 |
| 원격 결과 불명 | 상태 확인. 자동 재실행 없음 |
| 취소 접수 | 취소 요청 중. 확인 후 완료 |
| 평가 오류 | 근거 확인·재평가 |
| 예산 도달 | 신규 배정 중지·정책 확인 |
| 원문 접근 불가 | 권한·마스킹 안내 |

데이터 없음·조회 오류·수집 지연을 구분한다. 입력 오류는 해당 필드에 수정 방법을 표시한다. 상태는 색과 텍스트를 함께 쓴다.

## 화면 API

기본 경로는 /api/v1이다. [Plugin API](02-plugin-spec.md)와 [온라인 평가 API](05-online-evaluation.md)를 재사용한다.

| 동작 | 추가 계약 |
|---|---|
| 설정 초안 | POST /config-drafts, PATCH /config-drafts/{id} |
| 프로필·버전 | POST /config-profiles, /config-profiles/{id}/versions |
| 활성 참조·복구 | GET·PATCH /agents/{id}/config-refs |
| 시험 실행 | POST /agents/{id}/runs |
| 실행 목록·상세 | GET /runs, /runs/{id} |
| 새 데이터셋 | POST /datasets |
| 평가기·버전 | POST /evaluators, /evaluators/{id}/versions |
| 수동 검토 | POST /evaluation-reviews |
| 사례 후보 | POST /dataset-candidates |
| 변경 이력 | GET /agents/{id}/change-events |

실행 입력은 업무 입력과 snapshot_id 또는 selection이다. 둘을 동시에 받지 않는다. 변경은 권한·버전 충돌을 검증한다.

## 데이터와 지표

kpap은 실제 설정·실행 상태·평가 조건·정책·분모를 제공한다. Langfuse는 관측·사용량·비용·연계 점수를 제공한다. 상세는 [v3 연동](08-langfuse-v3-integration.md)을 따른다.

점수는 유효 평가만 집계한다. 비교는 유효 쌍 수를 표시한다. 온라인 커버리지는 유효 평가 실행 수 / 대상 실행 수다. 여러 평가기는 각각 집계한다.

업무·평가 지연과 비용을 분리한다. 미상 비용·제외·취소·미시작 수를 표시한다. trace 수를 전체 운영 분모로 사용하지 않는다.

## 완료 기준

설정 시험 → 평가 비교 → 운영 품질 조사 → 데이터셋 환류를 조건 재입력 없이 이어야 한다. 업무 trace와 judge trace를 같은 문맥에서 조사해야 한다.

필터·초안·스크롤을 유지해야 한다. 표·트리·차트는 키보드로 탐색할 수 있어야 한다. 대형 데이터·원문은 점진 로딩한다. 사용성 과제로 완료 여부와 잘못된 상태 해석을 검증한다.
