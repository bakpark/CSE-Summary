# kpap 노드 작업공간 UX

검토용 v0.4. 여러 노드의 설정·실행·평가·이력을 한 화면에서 다룬다. 이 문서가 작업공간 배치의 기준이다.

## 화면 배치

~~~text
에이전트 · 환경 · 설정 버전       [실행 | 평가 | 추적]  [이력]  [수행]
──────────────────────────────────────────────────────────
노드 흐름              선택 노드 설정          결과·처리 과정
의도 분류              모델·프롬프트           고객 입력 / 데이터셋
  ↓                    지식·도구              응답 / 항목·비교
지식 검색 → 답변 생성   변경·검증               선택 노드 관측
──────────────────────────────────────────────────────────
이력 버튼 → 오른쪽에 실행·실험 이력 사이드바
~~~

노드 선택·편집은 본문에 둔다. 설정마다 별도 창을 열지 않는다. 이력만 사이드바로 연다. 넓은 화면은 세 영역을 함께 표시한다. 좁은 화면은 같은 작업공간 안에서 영역을 전환한다.

이력을 열면 본문을 재배치한다. 결과를 가리지 않는다. 노드 영역은 간단한 목록으로 축소할 수 있다.

데스크톱 기본 비율은 그래프 30%·설정 28%·결과 42%다. 이력은 220px로 열고 나머지 영역을 재배치한다.

## 노드 설정

| 기능 | 동작 |
|---|---|
| 노드 선택 | 흐름에서 선택하면 해당 설정·최근 실행 구간 표시 |
| 모델 | 노드가 지원하는 모델·파라미터 변경 |
| 프롬프트 | 버전·본문·변수 확인. 본문은 초안으로 편집하고 수행 시 내용 고정 |
| 지식 | 자원·검색 옵션 변경 |
| 도구 | 허용 도구·호출 옵션 변경 |
| 기본값 | 공통 설정 상속과 노드 고유값 구분 |
| 변경 확인 | 수정한 노드·필드에 표시. 기본값 복구 제공 |
| 검증 | 권한·스키마·필수 변수 오류를 해당 필드에 표시 |

선택 노드가 지원하는 항목만 편집한다. 다른 노드의 변경값은 선택을 바꿔도 유지한다. 노드 연결·수행 순서는 등록된 에이전트 정의에서 가져온다.

시험한 프롬프트를 재사용하려면 새 버전으로 저장한다. 기존 버전은 덮어쓰지 않는다.

## 실행 흐름

1. 사용자가 노드를 선택한다.
2. 모델·프롬프트·지식·도구를 변경한다.
3. 같은 화면에서 고객 입력을 작성한다.
4. 수행을 누르면 서버가 전체 노드 설정을 검증·고정한다.
5. 흐름에 노드별 대기·진행·완료·오류를 표시한다.
6. 결과에 최종 응답과 선택 노드의 실제 설정·입출력을 표시한다.
7. 이력에서 이전 실행을 열어 결과·설정을 확인한다.

프로필 저장 없이 초안으로 수행할 수 있다. 실행 중 편집은 다음 수행에만 적용한다. 현재 실행은 시작 시 확정한 설정을 유지한다.

노드만 시험하는 기능은 입력·의존 결과가 확보된 경우 제공한다. 결과에 부분 실행을 표시한다. 전체 에이전트 실행과 구분한다.

## 이력 사이드바

| 항목 | 표시·행동 |
|---|---|
| 목록 | 시각·입력 요약·수정 노드·결과·설정 버전 |
| 필터 | 실행/평가·상태·설정·기간 |
| 이전 실행 선택 | 본문에 읽기 전용 설정·결과·노드 상태 표시 |
| 현재 초안 복귀 | 편집값·선택 노드·입력을 복원 |
| 초안으로 가져오기 | 이전 설정을 복사한 뒤 새 실행 |
| 기준 지정 | 선택 이력을 비교 기준으로 고정 |
| 비교 | 노드별 설정 차이·출력·시간·점수 표시 |

이력을 열고 닫아도 초안을 유지한다. 과거 결과 조회는 현재 편집값을 덮어쓰지 않는다. 코드·노드 정의가 달라 적용할 수 없는 설정은 가져오기 전에 표시한다.

## 오프라인 평가 흐름

같은 작업공간에서 평가 모드로 전환한다. 노드 선택과 편집값은 유지한다.

1. 사용자가 노드별 후보 설정을 편집한다.
2. 결과 영역에서 데이터셋 버전·평가기·기준 실험을 선택한다.
3. 수행을 누르면 코드·노드 정의·설정·데이터·평가기 버전을 고정한다.
4. 결과 영역에 진행·완료 항목·점수·오류를 표시한다.
5. 항목을 선택하면 해당 실행의 노드 상태와 관측을 표시한다.
6. 기준·후보의 응답·노드별 설정 차이를 비교한다.
7. 수정 후 같은 조건으로 새 실험을 수행한다.

반복·병렬도·제한시간·예산은 고급 옵션에 둔다. 평가를 시작하기 위해 다른 화면이나 단계별 마법사로 이동하지 않는다.

평가 이력은 같은 사이드바에서 실험 단위로 표시한다. 항목 상세는 본문에서 연다. 업무 trace와 judge trace를 구분한다.

## 추적 화면

추적 모드는 호출 계층과 관측 상세를 중심으로 표시한다. Tree/Timeline 전환·검색·입출력·메타데이터·점수를 제공한다. 업무와 평가기 추적은 분리한다. 편집용 그래프는 실행·평가 모드에 유지한다. 액션별 상태는 [사용자 시나리오](10-user-scenarios-and-screens.md)를 따른다. 현재 데이터는 모킹이다.

## 연동 계약

등록 정보는 node_id·이름·연결·노드 정의 버전·수정 가능 필드를 제공한다. 요청 설정은 node_id별 모델·프롬프트·지식·도구 변경값을 가진다.

런타임은 노드별 실제 적용값을 보고한다. 관측은 run_id·node_id·invocation_id·observation_id를 연결한다. 반복 수행 노드는 호출별 관측을 유지한다.

kpap은 노드 정의·설정·실행 이력을 제공한다. Langfuse는 연결된 노드 관측을 제공한다. 노드 관측이 없으면 미계측·수집 대기를 구분해 표시한다.

## 완료 기준

노드별 설정 수정 → 수행 → 관측 조사 → 이전 결과 확인 → 재평가를 한 화면에서 완료해야 한다. 이력 조회와 모드 전환은 현재 초안을 보존해야 한다. 요청값과 노드별 실제 적용값을 확인할 수 있어야 한다.

## SDK 응답 기반 표시

[그래프·A2A 규약](../agentic%20platform/kpap-graph-minimal-contract.md)의 nodes·edges로 흐름을 표시한다. configSchema·editable로 편집 필드를 만든다. 지원하지 않는 규격은 오류로 표시한다. 버전 충돌 시 재조회하고 초안 재적용 여부를 사용자가 판단한다. 프로토타입의 SDK 연동 화면은 JSON 가져오기·네 설정 편집·A2A 요청·모의 적용값·검증 오류를 제공한다. 임의 원격 서버 호출은 제공하지 않는다.
