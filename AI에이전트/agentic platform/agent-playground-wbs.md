# Agent Playground WBS 상세

> 작성일: 2026-10-07. 상태: 10주 병행 개발 예시.
> 관련 문서: [상위 기획](./agent-playground-draft.md).

각 Phase의 작업 규모는 6주로 잡는다. Phase0는 1~6주, Phase1은 5~10주로 배치한다. 2주를 겹친 10주 예시이며 확정 납기를 뜻하지 않는다. 주차별 표는 [상위 기획의 5.3 WBS 일정](./agent-playground-draft.md#53-wbs-일정)에서 확인한다.

| 컴포넌트 | Phase0 작업 범위 | Phase1 작업 범위 | 완료 기준 | 의존성 |
| --- | --- | --- | --- | --- |
| Agent Spec·Python SDK | 정의·실행·기록 계약, 내보내기, Stage 실행 | Builder·plugin 호환 연동과 보완 | SDK 에이전트를 배포 없이 시험한다. Builder import 후 커스텀 구현을 보존한다. | 모든 컴포넌트가 사용할 공통 계약을 먼저 확정한다. |
| Playground 형상·빌드 관리 | 별도 저장소, 형상 등록, 패키지와 환경 준비 | 실험 작업본, 변경 이력, 변경점 공유 | 기준 형상과 실험 이력을 유지한다. 형상별 실행 패키지를 고정한다. | SDK의 정의·패키지 계약. |
| Stage Runner | Python 실행, 세션, 격리, 시험 환경 연결 | Builder의 시험 실행 연결 | SDK와 Builder에서 같은 형상을 실행한다. 실패 기록을 형상과 연결한다. | SDK의 실행 계약과 준비된 실행 패키지. |
| 평가 도구 | 평가 계약, 테스트 셋, 실행 기록, 버전 비교 | 공동 결과 조회와 평가 근거 연결 | 고정 조건으로 버전을 비교한다. 선정 실험의 평가 근거를 공유한다. | Runner 실행 기록과 Playground 형상 식별자. |
| Agent Builder | — | 형상 import, 허용 설정 편집, 시험·결과 화면 | 기획자가 설정을 실험하고 변경점과 평가 근거를 공유한다. | 공통 정의·수정 권한 계약. 실제 연결에는 형상 관리·Runner·평가 도구가 필요하다. |
| 개발자 plugin | — | 형상 import, 파일 대응, 변경점 조회, 선택 반영 | 실제 프로젝트 로컬에서 변경점을 검토·반영한다. 충돌을 확인한다. | 공통 import·파일 대응 계약과 Playground 변경점 API. |

공통 계약은 1~4주에 확정한다. Builder와 plugin은 5주부터 확정 계약과 모의 응답으로 개발한다. Phase0 전체 완료를 기다릴 필요는 없다. 실행·평가 경로가 준비되면 실제 연동을 확인한다.

Phase0의 SDK 시험·버전 비교는 5~6주에 검증한다. Phase1의 기획자 실험·개발자 반영은 9~10주에 검증한다. 실제 서비스 형상은 기존 프로젝트에서 관리한다. Playground 형상은 KPAP의 별도 GitHub 저장소에서 관리한다.

컴포넌트별 병행 개발을 가정한 러프 일정이다. 주차는 작업 기간이며 인일을 뜻하지 않는다. 투입 인원과 파일럿 검증 결과에 따라 조정한다.
