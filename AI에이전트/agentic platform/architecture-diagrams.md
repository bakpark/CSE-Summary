## 용어 원칙

이미 사내에서 이름이 정해진 `Agent Stage Runner`, `Tool Gateway`, `CCAB`는 그대로 사용한다. 그 외에는 `채널 연결`, `운영 관리`, `에이전트 관리`, `에이전트 실행 환경`, `검증`처럼 역할을 바로 이해할 수 있는 표현을 사용한다.

## 1. 플랫폼 구조

첫 번째 페이지는 다음 두 흐름을 보여준다.

- **만들기 및 검증**: 업무 담당자 → CCAB → Agent Stage Runner → 검증 → 에이전트 관리
- **사용 및 실행**: KPAP(Web)·Claude Desktop·Slack → 채널 연결 → 에이전트 실행 환경 → 운영 관리 → Tool Gateway → 업무 시스템

`Agent Stage Runner`는 에이전트를 만드는 동안 사용하는 시험 환경이고, `에이전트 실행 환경`은 검증과 배포가 끝난 에이전트를 실제 업무에 사용하는 환경이다.

## 2. Agent의 정의와 운영 단계

> **Agent는 반복 업무를 수행하기 위해 목표, 입력과 결과, 업무 절차, 지식과 도구, 권한과 승인을 함께 담은 실행 단위다.**

Agent는 세 가지 기준으로 관리한다.

1. **업무 정의**: 무엇을 하고 언제 끝나는가
2. **사용 범위**: 어떤 자료와 도구를 누구의 권한으로 사용하는가
3. **검증 기록**: 어떻게 시험했고 어떤 버전이 실행됐는가

운영 단계는 `업무 정리 → 초안 → 실행 준비 → 검증 → 배포 버전 → 운영 중 → 관찰·개선`으로 표현한다. 변경할 때는 운영 중인 버전을 직접 고치지 않고 새로운 초안으로 시작한다.

## 3. Prompt만 관리하는 방식과의 차이

Prompt만 관리하면 지시 내용은 재사용할 수 있지만 실행 환경, 권한, 테스트와 변경 이력을 함께 관리하기 어렵다.

실행 가능한 Agent는 다음을 하나의 배포 버전으로 관리한다.

- 업무 정의
- 업무 절차
- 지식과 도구
- 실행 환경
- 권한과 승인
- 테스트와 검증
- 버전과 실행 기록

핵심 차이는 다음 한 문장으로 설명한다.

> **같은 Agent를 여러 채널에서, 같은 권한과 품질 기준으로 사용한다.**
